## Bug Report — "Output Sizing & Quality" Settings Not Applied in "Batch Preset Renderer" (SVG Recolor Section)

### 1. Issue Summary
There is a **significant discrepancy** between the intended **"Output Sizing & Quality"** settings (DPI / JPG) and the actual output files generated by the **"Batch Preset Renderer"** under the **"SVG Recolor"** section.

User-selected parameters — including:

- **Target Width (px)**
- **Target Height (px)**
- **DPI**
- **JPG Export Quality**

— are **not being applied** to the **"Download All Collages"** output. The downloaded files do not reflect the user's chosen settings, resulting in incorrect dimensions, resolution, and compression quality.

---

### 2. Root Cause (Likely)
The current logic may be:

- **Ignoring** the "Output Sizing & Quality" values when generating collages
- Using **hardcoded defaults** (e.g., 72 DPI, original canvas size, low JPG quality) instead of user input
- Failing to **pass the selected parameters** from the UI to the collage-generation function
- Applying settings only to **single downloads** but not to the **"Download All Collages"** bulk/ZIP output
- Missing a **shared configuration object** between the single-download and bulk-download pipelines

---

### 3. Requested Fix — Full Application of User Settings
Please resolve this issue **completely** so that the output accurately reflects the user's selected settings.

**Specifically:**

- **Target Width (px)** and **Target Height (px)** must be applied to every collage in the "Download All Collages" output
- **DPI** (100 / 150 / 300) must determine the final raster resolution of each collage
- **JPG Export Quality** must be honored during encoding for all JPG collage outputs
- Settings must apply **equally** to:
  - Single collage downloads
  - "Download All Collages" (bulk/ZIP) downloads
  - All formats (SVG, PNG, JPG)
- **No hardcoded fallbacks** should override user-selected values
- Output must match **preview / real-time estimates** shown in the UI
