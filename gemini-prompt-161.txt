## Kids Facts Book — Dynamic Index Generation and Correction Logic

In the **Kids Facts Book**, the current **Index section is not being generated/indexed correctly**. The index must be rebuilt so that it is based on the **actual content and pagination of the current book**, not on a fixed template, previous book, or cached index data.

The attached reference PDF is the current book and should be treated as the reference for understanding the existing interior structure. 

### Required Implementation

Every time a **new book is created**, the application must completely regenerate the index from that new book's actual interior content.

The workflow must be:

```text id="w0o2zi"
Generate New Book
        ↓
Generate complete interior manuscript
        ↓
Finalize all pages and page numbers
        ↓
Read the complete finalized book content
        ↓
Identify all indexable subjects/categories/facts
        ↓
Find the actual page number for each item
        ↓
Generate the Index from the current book
        ↓
Insert the Index into the manuscript
        ↓
Recalculate pagination if Index insertion changes page numbers
        ↓
Regenerate / revalidate Index
        ↓
Export final PDF
```

### Important: Read the Entire Current Book

The index-generation system must **read and analyze the complete current book interior** before creating the index.

Do not generate the index from:

* The previous book's index
* A fixed list of subjects
* Hard-coded page numbers
* Book 1 data
* Cached manuscript data
* Static chapter/page mappings
* Only the first few pages

The current PDF shows that the book contains multiple levels, fact sections, special sections, quizzes, answer keys, and an **ALPHABETICAL SUBJECT INDEX** section.  

### Dynamic Index Rules

For the current book:

* Read every fact title and relevant subject/category.
* Identify the actual index terms that occur in the book.
* Determine the exact page number where each item appears.
* Include only subjects/items that actually exist in that book.
* Do not include subjects that are missing from the current book.
* Do not carry over incorrect entries from an earlier book.
* Do not assume that the same facts or subjects appear on the same pages in every new book.

### Page Number Accuracy

The index page number must correspond to the **final printed PDF page number**, not:

* Internal array index
* Zero-based page index
* Temporary preview page
* Manuscript record number
* Old-book page number

For example, if a fact appears on PDF page 42, the index must show the correct final book page number **42** according to the book's actual printed pagination scheme.

### Recalculate After Index Insertion

If the Index itself is inserted before the final pages are completed, inserting or removing pages can shift later page numbers.

Therefore:

```text id="4qxfzv"
Build Book
   ↓
Calculate Initial Pages
   ↓
Generate Index
   ↓
Insert Index
   ↓
Pagination changes?
   ↓
YES → Recalculate all affected page numbers
   ↓
Regenerate Index
   ↓
Validate again
   ↓
NO → Finalize PDF
```

The final Index must always match the **final page numbering**.

### New Book Requirement

When the user creates **Book 2, Book 3, Book 4, etc.**, the index must be generated again from that specific book.

Example:

```text id="p8y7d9"
Book 1
→ Read Book 1
→ Generate Book 1 Index

Book 2
→ Read Book 2
→ Generate NEW Book 2 Index

Book 3
→ Read Book 3
→ Generate NEW Book 3 Index
```

Never reuse Book 1's index for Book 2 or later books.

### Preserve Existing Index Design

Keep the existing Index page's visual style, typography, spacing, and overall layout unless a correction is required for accurate content.

Preserve:

* Index title
* Font family
* Font sizes
* Colors
* Alignment
* Page layout
* Page margins
* KDP-safe positioning

Only the **index content, terms, ordering, and page numbers** should dynamically change according to the current book.

### Index Sorting

Keep the existing **alphabetical subject-index approach** shown in the reference book, but populate it dynamically from the current manuscript. 

Sort index terms alphabetically and ensure:

* No duplicate entries.
* No duplicate page numbers for the same occurrence.
* Multiple valid page references are grouped correctly when the same subject appears on multiple pages.
* Terms are normalized consistently so minor formatting differences do not create duplicate index entries.

### Validation Before PDF Export

Before the final PDF is downloaded:

```text id="w8r8oh"
Index Entry
   ↓
Does the term exist in the current book?
   ↓
YES
   ↓
Does the listed page actually contain that term/fact?
   ↓
YES
   ↓
Does the page number match final PDF pagination?
   ↓
YES → PASS

NO → Fix index entry
```

Run this validation for **every index entry**.

### Critical Requirement

The index must be **content-driven and book-specific**.

Whenever the user changes the book and creates a new manuscript, the system must:

**Read the complete new interior → identify the actual subjects/facts → locate their final pages → generate a new alphabetical index → validate the page numbers → export the final PDF.**

Do not use the previous book's index, cached page numbers, or hard-coded index data under any circumstances.
